# SkillProof · 技能实证

让 AI 技能的能力有据可查。独立项目，与 OpenAI 无官方隶属或认证关系。

## 本地运行

需要 Node.js 22.12+（推荐 24 LTS）与 pnpm。

```sh
pnpm install
pnpm dev
```

打开终端显示的本地地址，默认 http://127.0.0.1:5173。

`pnpm dev` 同时启动 Vite 和本机 SQLite API（127.0.0.1:8787）。也可以单独运行 `pnpm server`。默认数据库位于 `.skillproof-data/skillproof.sqlite`（已忽略，不提交）；用 `SKILLPROOF_DATA_DIR` 和 `SKILLPROOF_PORT` 可指定目录或 API 端口，修改端口时需同步调整 Vite 代理。

“真实评测”页面可同步本地档案/完整报告到本机服务、提交后台任务、取消任务、查看日志及拉取结果。服务串行执行最多 20 个待处理任务；关闭页面不会终止后台任务，服务重启会将中断的运行中任务标记失败，保留排队任务继续处理。服务端使用固定 Node Worker 适配器、输入/页数/输出/时间限制和 128 MB V8 老生代堆限制（不是整个进程硬内存上限），不支持不受信脚本。档案版本历史不可覆写，报告入库前核对证据。浏览器导入报告的来源与服务端执行来源在数据库中分开记录。

API 只监听回环地址、拒绝非本机 Host 和跨来源写入，不开放 CORS。当前没有多用户身份认证，适用于本机单用户；不得直接将私有管理 API 暴露到公网。可通过页面导出本机服务全部档案、结果和任务。与原有演示工作区备份格式不同。

```sh
pnpm test       # 数据聚合、筛选、存储校验和示例完整性
pnpm build      # TypeScript 检查与生产构建
pnpm preview    # 预览 dist 中的构建产物
```

## v0.1 范围

- 真实技能档案：从静态检查页保存原文，或在“真实档案”中新建；编辑创建不可变版本，包含声明能力、环境、权限和原文 SHA-256。档案存储在当前浏览器，可单独导出完整版本历史；当前工作区备份不包含档案，迁移前应单独导出。声明不等于已验证能力。

- 技能发现：关键词搜索、分类、收藏、通过率与耗时排序。
- 技能检查：上传 UTF-8 编码的 `.md` 文件或粘贴真实 `SKILL.md`，解析 YAML、检查必需字段与正文、定位问题行，导出带文本 SHA-256 的静态检查报告。
- 能力档案：支持范围、能力边界、环境、权限、示例测试明细及 JSON 导出。
- 技能对比：最多选择 3 项，逐项查看能力与运行条件。
- 评测基准：4 类设计模板，覆盖 PDF、表格、文档转换和内容校验。
- 演示评测：选择技能后回放预设结果，本地保存最近 100 条记录，可导出 JSON。
- 记录管理：按技能、版本、编号搜索，按基准筛选，按创建时间排序；查看历史明细、单条删除或清空全部记录，删除前需要确认。
- 历史快照：新记录保存创建时的技能版本、基准版本、运行环境和测试明细；旧记录继续保留摘要，不补造缺失明细。
- 报告导出：支持单条报告和批量导出当前筛选结果。评测报告格式为 `0.2.0`，`evidenceStatus` 标注 `demo-snapshot` 或 `summary-only`；能力档案仍使用原有 `0.1.0` 格式。
- 工作区备份：通过顶部“备份与恢复”导出收藏、记录和历史快照，支持校验 JSON 文件并预览合并结果；文件只在浏览器中读取。
- 桌面与移动端布局、键盘导航、原生模态框、减少动态效果支持。

**示例目录中的名称、版本、用例及指标均为虚构演示数据。** 点击“开始演示”只会在约 1.5 秒后保存静态示例结果；显示的秒数是示例测试集的预设总耗时，不是回放耗时。真实档案、固定 PDF 基准和实际执行记录在独立页面展示；不同基准的分数不可直接排名。

### 真实技能文件的静态检查

进入“技能检查”，上传 `.md` 文件或直接粘贴内容。检查器使用 `yaml` 解析器读取前置元数据，检查 `name`、`description` 是否为非空字符串、YAML 是否包含重复键以及正文是否存在。格式依据：[OpenAI 官方技能文档](https://developers.openai.com/plugins/build/skills)。当前规则版本为 `0.1.0`，只覆盖上述基础结构，不是完整的官方兼容性验证。

输入/输出标题和列表式步骤属于**可选写作建议**，不作为基础结构失败的原因。代码围栏中的示例不参与章节、列表和链接识别。资源引用仅识别常见 Markdown 链接，不检查目标文件或链接是否可用，也不代表完整依赖清单。

文件大小上限为 256 KB，仅接受 UTF-8 文本。内容在浏览器中处理，切换项目内页面会保留当前输入；刷新后清空，不进入演示评测记录或工作区备份。编辑内容会使旧检查结果失效，需要重新检查。导出报告类型为 `skillproof-static-inspection`、`mode: "static"`，包含规则版本、检查项及 SHA-256；指纹基于实际检查的 UTF-8 文本，不保证等于原始文件字节的哈希。

静态检查不执行技能或代码、不调用模型，也不认证能力、结果质量或安全性。Markdown 内容和资源路径以纯文本显示。

当前提供本机 SQLite 后台、固定 PDF 适配器和任务队列；没有多用户登录、任意技能安装或语言模型调用，不需要 API Key。收藏和演示记录仍保存在当前源地址的浏览器 localStorage，清除站点数据会丢失；切换端口会使用另一份存储。演示导出标注 `demo`，静态检查标注 `static`，真实执行标注 `executed`，三者分开保存。

### 工作区迁移

1. 点击顶部“备份与恢复”，选择“导出工作区备份”。
2. 在另一浏览器打开项目，进入同一弹窗，选择备份 JSON 文件（最大 2 MB）。
3. 查看新增收藏、记录数量和跳过提示，再点击“合并导入”。

工作区备份使用 `format: "skillproof-workspace"`、`version: 1`，与单条/批量报告文件不同，不能相互替代。同编号记录保留本地版本，重复导入不会产生重复记录。恢复只填补最近 100 条记录限制内的空余位置；空间不足时优先导入备份中时间较新的新记录，已有记录不会因恢复而被删除。未知收藏会跳过，损坏的记录或不一致的快照会使整份文件校验失败。备份包含演示数据，导入不会赋予其真实评测或认证含义。

## 项目结构

```text
src/
  App.tsx       页面和交互
  data.ts       虚构技能与基准模板
  lib.ts        聚合、搜索与持久化数据校验
  runs.ts       评测快照、历史筛选与报告格式
  workspace.ts  工作区备份校验和合并策略
  inspector.ts  SKILL.md 解析、静态检查与内容指纹
  components/   评测记录管理与可访问模态框
  types.ts      Skill / Suite / Run 类型
  styles.css    响应式界面
tests/
  domain.test.ts
  runs.test.ts
  workspace.test.ts
  inspector.test.ts
public/
  favicon.svg
```

技术栈：React、TypeScript、Vite、Lucide 图标、YAML 解析器。字体通过 Google Fonts 加载；网络不可用时使用系统字体，核心功能不依赖外部字体。

## 后续接入位置

完整真实评测报告保存技能原文、清单原文、逐项输入输出哈希、评分版本、PDF.js 版本、执行环境和资源限制，明确标注未调用大模型。导出前重新核对哈希与评分；缺少完整证据的旧记录需要重跑。复现命令：`node --experimental-strip-types scripts/reproduce.mjs <report.json>`。命令只使用本仓库固定适配器与固定基准文件，不执行报告中的技能原文。它核对每个实际输出哈希和通过/失败判定；不要求耗时相同。来源仍是本地测量，不是第三方认证。

执行边界：浏览器在独立 Worker 中运行固定 PDF 适配器，Worker 只接收文件字节，覆盖并锁定网络 API；不提供目录访问或任意脚本入口。输入最多 8 MB、30 页、输出文字最多 1 MB、单文件时限 10 秒。取消、超时和失败均销毁 Worker。页面只从固定本地基准路径读文件并核对哈希。浏览器管理其堆内存，没有独立硬内存配额；这是固定受信适配器的限制边界，不是用于执行不受信第三方代码的操作系统沙箱。

“真实评测”运行固定登记的 `pdfjs-text` 适配器（PDF.js 版本由锁文件固定），真实读取 5 项 PDF 输入并按逐页文本评分。点击“登记内置 PDF 提取档案”建立对应原文；只有明确声明 `metadata.skillproof.adapter: pdfjs-text` 的档案可执行。实际执行的是登记适配器，不是任意 Markdown 指令，也不调用大模型。每个记录标注 `mode: executed`，与演示记录分开；保存档案版本、输入输出哈希、错误、耗时和评分依据，最多保留 50 条，可单独导出。

真实 PDF 基准位于 `public/fixtures/pdf-text-v1/`，5 个文件均由项目生成，使用 CC0-1.0 发布。`manifest.json` 保存逐页预期文本、输入 SHA-256 和评分规则。用 `node scripts/generate-fixtures.mjs` 可确定性重建；测试验证文件指纹、页序与空白页评分。基准只覆盖英文/ASCII 数字 PDF，不测试扫描件、中文字体、公式或多栏版式。

1. 将 `data.ts` 中的技能档案与基准模板迁移到后端存储，加入发布者身份与版本溯源。
2. 用后端任务 API 替换 `App.tsx` 的 `startRun` 演示计时器；真实执行需独立沙箱、权限控制、超时和资源限制。
3. 为每类基准增加可分发的测试文件、确定性检查与人工复核流程。
4. 报告补充模型版本、技能内容哈希、测试集哈希、真实运行环境与执行证据，再讨论认证或公开排名。
